# Learner Profile

## Initial Idea
A simple Python web app: paste a message, it says whether it looks like a **scam** or **safe**, and **highlights the warning words**. Small proof of concept for this hackathon — simple and working end to end. Firm out of scope: **no login, no phone number, no account system, no phone connection** — one paste box on a simple web page.

## Demonstrated Technical and Agent Experience
Reported: beginner in coding and data science; 2nd-year CSC (Data Science) student; wants to use Python.
AI: has used chat to ask questions; has **not** used a coding agent to edit files in a project.
Evidence: “I’m a beginner and I’m using Python.” / “I’ve used AI chat to ask questions, but I haven’t used a coding agent to edit files in a project.”

## Planning-Workflow Experience
New to plan-first / spec-driven work. Has not written a spec before.
Evidence: “I haven’t written a spec before.”

## Desired Learning Outcome
Practice working with a coding agent, ship a small working app, and by the end **explain what each file does** and **check whether the app matches the spec**.

## Learning Moments
Not yet — onboarding only.

## Interests, Inspirations, and Goals
Wants to finish a real project for a resume. The idea is a small, demoable scam-message checker.

## Vocabulary and Concepts Likely to Need Explanation
Likely need brief, plain-language explanations of: spec/PRD, coding-agent workflows (files in a repo vs. chat), web-app basics (server vs. page), and whatever stack we pick later.
They already named Python and “simple web page / paste box.” Don’t assume they know Flask/FastAPI, HTML templates, or deployment until mentioned.

## Collaboration and Communication Preferences
- Explain each step briefly before doing it.
- Keep the scope small.
- One question at a time.
- Guided explanations (not a preference for extra-concise onboarding).

## Areas Where the Learner Wants Ownership
Explicit product boundary they want honored: no login, no phone, no account system. They asked to keep those out of the spec.

## Likely Support Needs
Walk through agent steps (what a file is, why we’re changing it). Keep technical choices simple and explained before asking them to agree. Setup help likely needed when we start running a local web app.

markdown

- How “scam vs safe” is decided (rules vs. a model) is a later spec choice; don’t invent it here.
